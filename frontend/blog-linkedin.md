# 바둑에서 배운 코딩의 기술 — 碁Vibe 개발기

**"다음 한 수가 전체 판세를 바꾼다"**

---

6개월 전, 저는 AI 교육 플랫폼(BlueL)을 개발하면서 한 가지 문제에 부딪혔습니다.

> "이 코드베이스에서 지금 당장 뭘 고쳐야 가장 큰 효과가 있을까?"

SonarQube는 수백 개의 경고를 쏟아냈고, GitHub Copilot은 한 줄씩만 봤습니다. 전체 판세를 읽고, **가장 임팩트 있는 한 수**를 찾아주는 도구는 없었습니다.

그때 떠오른 건 바둑이었습니다.

---

## 왜 바둑인가

AlphaGo가 이세돌 9단을 이겼을 때, 모두가 AI의 승리라고 말했습니다. 하지만 저는 다른 것에 주목했습니다.

**AlphaGo의 37수.**

해설자들이 "실수"라고 했던 그 수가, 50수 후에 판 전체를 장악하는 묘수(妙手)였다는 것.

소프트웨어 개발도 똑같습니다.

| 바둑 | 소프트웨어 개발 |
|------|----------------|
| 포석(布石) | 프로젝트 아키텍처 설계 |
| 정석(定石) | 디자인 패턴 적용 |
| 수읽기 | 3수 앞의 영향 분석 |
| 묘수(妙手) | 하나의 리팩토링이 전체를 바꾸는 순간 |
| 승률 | 프로젝트 생존 확률 |
| 기보(棋譜) | 개발 과정 기록 |
| 패(劫) | 순환 의존성 |
| 단수(Atari) | 위험한 모듈 |

이 매핑이 단순한 비유가 아니라 **실제로 작동하는 프레임워크**가 될 수 있다면?

碁Vibe를 만들기 시작했습니다.

---

## 만다라와 바둑판의 만남

碁Vibe의 첫 화면은 **만다라 매트릭스**입니다.

가로축은 프로그래밍 언어. 세로축은 프레임워크.
교차점은 바둑판의 착점(着點)이자 만다라의 셀.

**Python × Streamlit**, **TypeScript × Next.js**, **Rust × Axum**...

언어와 프레임워크를 선택하면, 바둑판 위에 첫 돌이 놓입니다.
이것이 당신의 **포석**입니다.

---

## 5개의 질문으로 세계가 열린다

12개 설정 항목을 채우라고 하면 사람들은 떠납니다.
인지부하(Cognitive Load) 이론이 말하는 것 — **작업 기억의 한계는 7±2**.

그래서 5개만 물어봅니다:

1. **무엇을 만들고 싶은가?** (한 문장)
2. **개발 경험 수준은?** (입문/중급/고급)
3. **하루 투자 가능 시간은?**
4. **결과물 품질 목표는?** (MVP/정교/프로덕션)
5. **어떤 AI를 쓸 것인가?** (Claude/GPT/Gemini/Groq/로컬)

나머지 7가지(개발 스타일, 인지 유형, 동기, 사전지식, 예상 난점, 배포 환경, 팀 규모)는 **AI가 자동 추론**합니다.

"실시간 주식 대시보드"라고 입력하면:
- 개발 스타일 → 데이터 먼저 (data-first)
- 배포 환경 → Streamlit Cloud 또는 Vercel
- 예상 난점 → 실시간 WebSocket, 차트 렌더링 최적화
- 팀 규모 → 1인 (사이드 프로젝트 톤)

이 모든 것이 5초 안에 추론됩니다.

---

## 인지과학 × 개발 7단계

각 개발 단계에 인지과학 이론을 매핑했습니다.
세계 최고 수준의 개발자부터 초보까지, 같은 단계를 밟되 **깊이가 다릅니다**.

### ⚖️ 인지부하 관리 → 포석 (프로젝트 설계)
Feature-based 디렉토리 구조. 모듈 간 의존성 최소화.
초보에게는 보일러플레이트를. 고수에게는 아키텍처 원칙을.

### 🔗 정교화 설계 → 정석 (아키텍처 + 데이터 모델)
디자인 패턴(Observer, Strategy)을 기존 경험과 연결.
"이건 네가 전에 써본 Redux의 구독 패턴과 같아."

### 🌊 몰입 구현 → 중반전 (핵심 기능 개발)
1-2시간 딥워크 세션. TDD 레드-그린-리팩터 리듬.
난이도를 실력에 맞춰 조절 — 칙센트미하이의 Flow 이론.

### 🧠 인출 테스트 → 선수 (테스트 + 디버깅)
단위 테스트 작성 = 인출학습. 배운 것을 코드로 증명.
"이 함수가 뭘 하는지 테스트로 설명할 수 있는가?"

### 👨‍🏫 파인만 리뷰 → 묘수 (코드 리뷰 + 리팩토링)
PR에 Why를 명시. ADR(Architecture Decision Record) 작성.
"초등학생에게 설명할 수 없다면 이해하지 못한 것이다."

### 🎨 이중부호화 UI → 묘수 (UI/UX + 시각화)
Mermaid 다이어그램 + 코드. 시각과 언어를 동시에 사용.
인간의 뇌는 텍스트만으로는 절반만 기억합니다.

### 📅 간격 배포 → 끝내기 (배포 + 유지보수)
CI/CD 파이프라인. 카나리 배포. 주간 리팩토링 세션.
에빙하우스 망각곡선 — 간격을 두고 반복해야 기억에 남는다.

## AI가 묘수를 찾는 방법

碁Vibe의 핵심은 **각 단계에서 AI가 최적의 프롬프트를 생성**하는 것입니다.

사용자가 "인증 모듈"을 개발 중이라면:

**초보에게**: "JWT 토큰이 뭔지 비유로 설명하고, 로그인 함수를 한 줄씩 작성해줘."

**중급에게**: "OAuth 2.0 PKCE 플로우를 구현하되, refresh token rotation을 포함해줘."

**고급에게**: "Zero-trust 아키텍처에서 mTLS + SPIFFE 기반 서비스 인증을 설계해줘."

같은 모듈, 같은 기능이지만 **수준에 맞는 묘수**가 다릅니다.

## 생성된 코드가 브라우저에서 바로 돌아간다

가장 자랑스러운 기능입니다.

WebContainer API를 통합해서, **생성된 코드가 브라우저 안에서 즉시 실행**됩니다.

```
5개 질문 응답
    ↓
AI가 Spec 생성
    ↓
AI가 실제 코드 작성
    ↓
WebContainer에서 npm install
    ↓
개발 서버 시작
    ↓
브라우저 내 미리보기 ← 여기까지 자동
```

다운로드하고, 터미널 열고, npm install 치고... 그런 과정이 없습니다.
"만들고 싶은 것"을 말하면, **30초 후에 돌아가는 앱**을 봅니다.

## 7개 AI 프로바이더, 20개 모델

특정 AI에 종속되지 않습니다.

- **Anthropic**: Claude Opus 4.6 / Sonnet 4.6 / Haiku 4.5
- **OpenAI**: GPT-4o / o3-mini
- **Google**: Gemini 2.5 Pro / Flash
- **Groq**: Llama 3.3 70B (초고속)
- **Mistral**: Codestral (코딩 특화)
- **DeepSeek**: R1 Reasoner
- **Ollama**: 로컬 실행 (무료, 인터넷 불필요)

API 키는 사용자 브라우저에만 저장됩니다. 서버로 전송하지 않습니다. 난독화 처리되어 localStorage에서도 평문으로 노출되지 않습니다.

## 기보(棋譜)로 기록하다

개발 과정은 SGF(Smart Game Format)로 기록됩니다.
바둑 기보 뷰어에서 열 수 있는 실제 기보 파일.

```
(;FF[4]GM[1]SZ[19]PB[Developer]PW[AI]
;B[dp]C[포석: 프로젝트 초기화 (Win-Rate: 15%)]
;W[pd]C[정석: 데이터 모델 설계 (Win-Rate: 32%)]
;B[qf]C[중반전: API 엔드포인트 구현 (Win-Rate: 58%)]
;W[nc]C[★묘수: 캐싱 레이어 추가 (Win-Rate: 78%)]
;B[rd]C[끝내기: CI/CD 배포 (Win-Rate: 92%)])
```

3번째 수에서 Win-Rate가 58%였는데, 4번째 묘수(캐싱 레이어)로 78%까지 점프.
이것이 묘수의 힘입니다.

## 보안

서비스를 공개할 때 가장 신경 쓴 것:

- **HSTS**: 2년 + preload (HTTPS 강제)
- **CSP**: X-Content-Type-Options, X-Frame-Options, X-XSS-Protection
- **CORS**: Strict-origin 정책
- **API Key**: XOR + Base64 난독화 (localStorage)
- **권한**: 카메라/마이크/위치 차단
- **감사**: npm audit 0 취약점 (프론트+백엔드)
- **Git**: .env, .pem, .key, .secret 전부 .gitignore
